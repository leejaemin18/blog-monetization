## 0. 이 프로젝트의 실행 구조

**Claude 세션은 블로그 도메인에 직접 접근할 수 없다.** (네트워크 차단)
모든 워드프레스 작업은 **GitHub Actions 러너**가 대신한다.

```
Claude → 워크플로우 dispatch → 러너가 WP REST API 호출 → 로그 출력 → Claude가 로그를 읽어 확인
```

그래서 지켜야 할 것:
- 새 워크플로우는 **main에 머지된 뒤에야** 실행할 수 있다 (GitHub 제약)
- 결과 확인은 항상 **로그를 읽어서** 한다. "됐을 것이다"로 넘기지 않는다

### 필요한 시크릿
| 이름 | 용도 |
|---|---|
| `WP_URL` | 블로그 주소 |
| `WP_USER` | 워드프레스 사용자 |
| `WP_APP_PASSWORD` | **응용 프로그램 비밀번호** (관리자 비밀번호 아님) |
| `OPENAI_API_KEY` 또는 `OPEN_API_KEY` | AI 썸네일·본문 이미지 생성 |
| `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET` | 지식iN 글감 조사 (네이버 클라우드 API HUB 키) |

## 1. 새 글 발행 — 표준 순서

### 준비
1. **주제 선정** — `docs/콘텐츠-로드맵.md`에서 고른다
2. **구조 결정** — `templates/제휴글-스타일가이드.md` 3.5 F 이력표를 보고 **최근 4편과 겹치지 않는 조합**을 고른다
3. **초안 작성** — `drafts/예시-<주제>.md`
   - 파일명은 반드시 `예시-`로 시작 (그 외 drafts는 gitignore됨)
   - 본문에 `[[IMG:키]]`, `[[PRODUCT:키]]` 토큰을 넣는다
4. **인포그래픽** — `assets/images/<키>/<이름>.svg` + 같은 폴더에 `alt.json`
5. **상품카드** — `assets/products/<키>.html`
   - 운영자가 준 **쿠팡 배너 HTML**(`<a href="link.coupang.com/a/..."><img src="...coupangcdn..."></a>`)에서 링크·이미지를 뽑아 카드로 조립
   - ⚠️ **iframe 배너는 쓸 수 없다.** 이미지 배너로 다시 받는다
6. **머지** — PR 만들어 main에 머지 (워크플로우가 파일을 읽으려면 main에 있어야 함)

### 발행 전 자동 감사 (필수)

```bash
python3 tools/compliance.py drafts/예시-<주제>.md    # 정책·문체
python3 tools/humanize.py  drafts/예시-<주제>.md --fix   # AI 티 (자동 수정 포함)
```

문서로만 둔 규칙은 지켜지지 않는다. 실제로 어겼던 것들을 검사로 옮겨놨다.
**이 두 검사는 `wp-rewrite-post.yml` 첫 스텝으로도 돌아간다** — 로컬에서 빼먹어도
발행 경로에서 막힌다. 정말 이유가 있을 때만 `skip_gate=y`.

**`compliance.py` — 정책·문체**
- 광고표시 문구·위치, 금지어, 링크 도배
- 굳어버린 상투구 · '우리 아이' 3회 이상
- 지어낸 1인칭 경험 → ERROR · 미치환 자리표시자(`__LINK1__`) → ERROR
- 깨진 한글(유니코드 이스케이프 사고로 실제 발생했던 문자열)
- 분량 · 내부링크 수 · 외부 링크 · GEO(도입부 답 요약, FAQ 형식)

**`humanize.py` — AI 티** (2.6절 참고)
- S1이면 발행 차단. `--fix`는 뜻이 안 바뀌는 삭제만 기계가 한다.

### 발행 (순서대로)
```
① wp-rewrite-post.yml      새 글 발행 (post_id 비우면 신규)
② wp-set-slug-tags.yml     영문 슬러그 + 태그 + 카테고리
③ wp-rehost-all.yml        쿠팡 배너 이미지를 우리 서버로 이전
④ wp-add-dynamic-banner.yml 하단 캐러셀 삽입
⑤ wp-faq-schema.yml        FAQ가 있으면 JSON-LD 주입 (GEO)
⑥ wp-inspect.yml           검증
```

**②~⑥은 ①이 완전히 끝난 뒤에 실행한다.** ①은 AI 이미지 2장 생성 때문에 약 2분 걸리고,
끝나기 전에 ③을 돌리면 리호스팅이 덮어써져 무효가 된다(실제로 겪은 실수).

### ①의 주요 입력값
| 입력 | 설명 |
|---|---|
| `post_id` | 비우면 신규 발행, 채우면 해당 글 재빌드 |
| `draft_path` | `drafts/예시-....md` |
| `image_dir` | `assets/images/<키>` (이 폴더의 SVG만 변환) |
| `product_dir` | `assets/products` 고정 |
| `category_name` | 정확한 카테고리 이름 |
| `thumb_prompt` / `mid_prompt` | AI 이미지 프롬프트 (영문, `no text, no logos` 필수) |
| `mid_anchor` | 중간 이미지를 넣을 **H2 제목과 정확히 일치**해야 함 |
| `status` | `publish` / `draft` |

### 발행 후 (운영자가 직접)
- **Rank Math 포커스 키워드 입력** — REST로 저장이 안 되는 항목이라 수동
  - ⚠️ **편집기를 새로고침한 뒤에** 입력할 것. 열어둔 낡은 탭을 저장하면 REST로 넣은 내용이 통째로 덮어써진다
- 메타 설명은 자동 생성되므로 굳이 손대지 않아도 된다

## 2. 워크플로우 카탈로그

### 발행·수정
| 파일 | 용도 |
|---|---|
| `wp-rewrite-post.yml` | **주력.** 초안 → 발행/재빌드 (이미지·상품카드·광고문구 전부 처리). 첫 스텝이 **발행 전 검사 게이트** — S1/ERROR면 워드프레스를 건드리기 전에 멈춘다. `skip_gate=y`로만 우회 |
| `wp-set-slug-tags.yml` | 슬러그·태그·카테고리 설정. `create_category=y`로 새 카테고리 생성 가능 |
| `wp-add-dynamic-banner.yml` | 모든 발행 글 하단에 쿠팡 캐러셀 삽입 (멱등) |
| `wp-rehost-all.yml` | 쿠팡 CDN 이미지를 우리 미디어로 이전 (**광고차단 대응**) |
| `wp-faq-schema.yml` | FAQ를 **FAQPage JSON-LD**로 주입 (GEO) |
| `wp-publish.yml` / `wp-full-post.yml` | 구버전 발행 경로 |
| `wp-insert-product.yml` / `wp-remove-product.yml` | 상품카드만 넣고 빼기 |
| `wp-insert-image.yml` / `wp-upload-image.yml` / `wp-images.yml` / `wp-thumbnail.yml` | 이미지 개별 작업 |
| `wp-style-disclosure.yml` / `wp-strip-disclosure.yml` | 광고표시 문구 스타일 변경·제거 |

### SEO
| 파일 | 용도 |
|---|---|
| `wp-seo-patch.yml` | 키워드 배치·내부링크·외부링크 주입 (글별 PLAN 하드코딩) |
| `wp-seo-apply.yml` | 슬러그·태그·제목 일괄 적용 |
| `wp-seo-expand.yml` | 분량 보강 |
| `wp-seo-audit.yml` / `wp-seo-meta.yml` | 진단 |

### 진단
| 파일 | 용도 |
|---|---|
| `wp-list-posts.yml` | **전체 글 상태 점검** — 상품카드·쿠팡링크·광고문구·다이나믹배너·내부링크 수 |
| `wp-inspect.yml` | 특정 글 본문 발췌 + 항목 체크 |
| `wp-status.yml` / `wp-settings.yml` | 사이트 설정 확인 |
| `site-check.yml` | 공개 페이지 확인 (인증 태그·robots.txt·사이트맵) |

### 지식iN
| 파일 | 용도 |
|---|---|
| `kin-unanswered.yml` | **주력.** 지금 시점 **답변 0개** 질문을 최신순으로 조회 |
| `naver-kin-find.yml` | 키워드 기반 글감 조사 (검색 API). **미답변은 못 찾는다** — 아래 참고 |

> 네이버 검색 API는 **답변이 달린 글만 색인**한다. 그래서 미답변 질문은 검색으로 찾을 수 없고,
> 카테고리 목록 페이지를 직접 파싱하는 `kin-unanswered.yml`을 써야 한다.
> 두 도구는 용도가 다르다 — 조사는 `naver-kin-find`, 답변 대상 찾기는 `kin-unanswered`.

## 2.5 GEO — 답변 엔진에 인용되기

SEO와 GEO는 목표가 다르다. 둘 다 챙긴다.

| | SEO | GEO |
|---|---|---|
| 대상 | 검색 엔진 | **답변 엔진** (ChatGPT · Claude · Perplexity · AI 개요) |
| 목표 | 순위 | **인용** |
| 신호 | 제목 · 메타 · 링크 · 속도 | **추출 가능한 구조 · 명시적 Q&A · 출처 · 엔티티** |

인용되려면 **뽑아 쓰기 좋은 형태**여야 한다. 그래서 글에 이 두 가지를 넣는다.

1. **도입부 한 문단 답 요약** — 결론을 먼저 던지는 형태. 답변 엔진이 그 문단을 그대로 인용한다.
   (예: 심장비대 글의 `**분당 30회.**`, 혼자 두기 글의 "먼저 답부터 드릴게요")
2. **명시적 Q&A** — `**Q. 질문**` + 답변 문단 형식. `wp-faq-schema.yml`이 이걸 읽어
   **FAQPage JSON-LD**로 만들어 본문 끝에 심는다.

```
wp-faq-schema.yml   post_ids 비우면 발행 글 전체 / dry_run=y로 먼저 확인
```

멱등이라 여러 번 돌려도 안전하고, FAQ가 없는 글은 건너뛴다.
저장 후 스키마가 실제로 남았는지까지 확인한다(테마·플러그인이 script를 제거할 수 있어서).

> FAQ를 매 글에 넣지는 않는다(3.5 D). 넣은 글에서만 스키마가 생긴다.

## 2.6 AI 티 제거 (humanize)

출처: [`epoko77-ai/im-not-ai`](https://github.com/epoko77-ai/im-not-ai) "Humanize KR" v2.3 (MIT).
한글 AI 글의 티를 10대 카테고리 70패턴으로 정리한 저장소다. 그쪽은 LLM 콜로 윤문하지만
**우리 러너에는 Claude API 키가 없다.** 그래서 같은 분류 체계를 셋으로 쪼개 파이프라인에 붙였다.

| 층 | 무엇 | 어디서 |
|---|---|---|
| 검사 | LLM 없이 도는 결정적 지표. S1이면 종료 코드 1 | `tools/humanize.py` · CI 게이트 |
| 자동 | 뜻이 안 바뀌는 삭제만 (연결어미 뒤 쉼표) | `--fix` |
| 지목 | 판단이 필요한 건 줄 번호로 찍어준다 | 초안 쓸 때 사람이 처리 |

### 임계는 우리 글을 실측해서 잡았다

taxonomy를 그대로 베끼지 않았다. **70개 패턴 전부를 우리 초안 11편에 돌려보고** 결과에 따라
셋으로 갈랐다 — 실제로 걸린 것 / 지금은 0건이라 방어선만 둔 것 / 측정하고 버린 것.

기준선 출처는 im-not-ai `empirical-validation.md` — AI 60편(3개 모델) vs **2022년 이전 발행**
한국어 산문 60편(AI 혼입 불가) 대조, 로그우도비 G² 검정.

#### ① 실제로 걸린 것 — 검사 발동

| 코드 | 패턴 | 우리 실측 | 임계 | 기준선 (AI vs 사람) |
|---|---|---|---|---|
| **C-8** | `A가 아니라 B` 대구 | 6편 전부, 3편은 3회 | 3회 = S1 | 5.8 vs 0.6 — **9.2배** (블로그 대비 18배) |
| **C-11** | 연결어미 뒤 쉼표 | 11편 전부 4~8회 | 6회 = S1 | 19.83% vs 4.10% — 4.84배 |
| **E-1** | 100자+ 장문 결핍 | 평균 20/1k, 5편은 0개 | 25/1k 미만 | 8.1 vs 91.3 — AI가 *못 쓰는* 축 |
| **E-2** | 같은 종결어미 연속 | 대개 2~3, 1편이 4 | 4연속 | — |
| **J-2** | 따옴표 강조 | 최대 8회 | 6회 | — |
| **A-10** | `~할 수 있다` 남발 | 최대 5회 | 6회 | 해요체라 느슨하게 |
| **C-4\*** | `**라벨** — 설명` 골격 반복 | 평균 6.5, 최대 9 | 8회 | 우리 자체 규칙 (3.5 D) |

\* 대시(—) 자체는 문제가 아니다. 88개 중 **72개가 목록 라벨**이고 블로그에선 읽기 편하다.
문제는 매 글이 같은 뼈대로 조립된다는 쪽이라, J-3(대시 남용)이 아니라 C-4(공식화)로 잡는다.

#### ② 지금 0건 — 방어선만 (`ZERO` 검사)

한 번이라도 나오면 문체가 흘러내리기 시작한 것이라 임계를 0으로 뒀다.

A-1 `~에 대해` · A-4 `~라는 점에서` · A-5 `~와 관련하여` · A-6 `~에 기반하여` ·
A-7 `가지고 있다` · A-8 이중 피동 · A-9 `~에 의해` 피동 · A-12 `만들어지다` ·
A-19 이중 조사 · B-4 `~라고 알려진` · C-1 `첫째/둘째` · C-6 섹션 안내문 ·
C-9 `1) 2) 3)` · C-10 콜론 부제 헤딩 · D-1~D-4 결산·과장 lexicon · D-5 의인화 주어 ·
D-6 `~할 때입니다` · F-2 이중 수식 · G-1 추측 종결 · G-2 이중 완곡 ·
H-1 문두 접속사 · H-2 문두 역접 · H-3 `이는 ~` · I-1 `것이다` · I-2 형식명사 강조

문서 단위 방어선: **C-12** 쉼표 포함률 45% 초과(우리 6~28%, 사람 26% / AI 61%) ·
**F-4** `~성/~적/~화` 12회 초과(우리 최대 7).

#### ③ 측정하고 버린 것

| 항목 | 왜 뺐나 |
|---|---|

| J-4 괄호 부연 | 대부분 `(확인 후 기입)`(우리 컴플라이언스 규약)과 기술 용어 풀이다. 오탐 |

| `metrics_v2.py` 통째 벤더링 | 위와 같은 이유. **규칙만 가져오고 채점 체계는 안 쓴다** |

### 자동 수정의 안전 장치

`--fix`는 **쉼표 삭제만** 한다. 다른 글자는 건드리지 않는다(초안 11편 62곳 적용 후 대사 확인).
'고'는 명사 끝소리로도 흔해서(사고·광고·참고·냉장고) 명사 목록으로 걸러낸다 —
"사고, 질병"의 쉼표는 지우지 않는다. 바꾼 곳은 전부 줄 번호와 함께 출력한다.

> **발행된 글에는 아직 적용 안 됨.** 초안(원본)만 고쳤다. 지금 살아 있는 11편에는
> 쉼표가 그대로 있다. 재빌드하면 SEO 패치가 날아가므로(`drafts/README.md`),
> 라이브 본문을 고치려면 REST로 쉼표만 지우는 워크플로우를 따로 만들어야 한다.

## 3. 지식iN 홍보

자세한 규칙은 `templates/제휴글-스타일가이드.md` **8절**. 요약하면:

- 답변 본문에서 **특정 제품을 추천하지 않는다** (지식iN 정책이 겨냥하는 형태)
- **쿠팡 링크를 답변에 직접 붙이지 않는다** (자동 필터 삭제·정지 위험)
- 블로그 링크를 달면 **끝부분에 제휴 관계를 공개**한다
- 링크는 **출처 칸**에, 하루 3답변 중 **링크는 1개까지**, 대상 글은 매번 다르게
- 답변 텍스트는 **코드블록으로 전달** (서식이 딸려가 배경색·글자색이 깨진다)

**현재 전략:** 계정이 초수이고 중수까지 채택 답변이 부족하다.
링크 있는 답변은 채택률이 낮으므로, **답변 0개인 최신 질문에 빠르게 답해 채택을 먼저 쌓는다.**

## 6. 컴플라이언스 (절대 어기지 않는 것)

- 제휴 글에는 **광고표시 문구를 첫 부분에** 넣는다 (발행 워크플로우가 자동 처리)
- 제휴 링크는 전부 `rel="nofollow sponsored noopener"`
- **가격·할인·쿠폰을 지어내지 않는다.** 확인 필요하면 `(확인 후 기입)`
- 금지어: 최고·무조건·100%·완벽·유일·강력추천·초특가
- **지어낸 1인칭 경험을 쓰지 않는다.** 운영자의 실제 경험이 아니면 독자를 향한 서술로
- 건강 주제는 **진료 우선**을 명시하고, 제품이 치료를 대신하는 것처럼 쓰지 않는다
