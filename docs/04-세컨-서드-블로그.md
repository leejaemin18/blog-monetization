# 세컨 · 서드 블로그 개설 (4강) — 제휴 수익화의 시작

이 프로젝트의 실제 수익화는 여기서 시작합니다.
애드센스 블로그(1~3강, 승인 대기 중)와 **분리된 제휴 전용 워드프레스 블로그**를 만듭니다.

> 애드센스 블로그는 *제이통관블로그 워드프레스 프로젝트*에서 별도 관리합니다.
> 여기서는 개설 방법만 참고하면 됩니다 → [`10-블로그-만들기-참고.md`](10-블로그-만들기-참고.md)

## 왜 분리하는가

- 애드센스 심사 중인 사이트에 머니 키워드를 섞지 않는다(강사 주장, 공식 근거는 없음)
- 무엇보다 **제휴는 별도 사업**입니다. 독자·주제·수익모델이 다른 사이트를 따로 운영합니다.
- 세컨 → 서드로 니치를 넓혀 채널을 늘립니다.

## 서브도메인 = 추가 비용 0원

- 메인 도메인 `wp-blog.co.kr`을 한 번 사면 서브도메인은 **무제한 무료**
  - 세컨: `coupon.wp-blog.co.kr`
  - 서드: `review.wp-blog.co.kr`
- ⚠️ 등록비는 0원이지만 호스팅·DNS·SSL 비용/제약은 존재

## 서버·블로그 수 관계

| 구성 | 블로그 수 | 추가 비용 |
|---|---|---|
| 서버 1대 (기본) | 1개 | - |
| 서버 1대 + 멀티서비스 | 최대 3개 | 월 4,000원 |
| 서버 2대 + 멀티서비스 | 최대 6개 | 서버비 + 4,000원 |

→ 세컨·서드는 **서버 1대 + 월 4,000원**이면 충분 (기존 애드센스 블로그 서버에 얹거나 별도 서버)

## 세컨 블로그 개설 순서

### 1. 서브도메인 추가
호스팅 콘솔 → 프로필 → 내 콘솔 관리 → 도메인 관리 → 내 도메인
→ 서브도메인 추가 → 이름 입력(예: `coupon`) → 추가하기

### 2. 블로그 추가 (멀티사이트)
호스팅 관리 → 서버 → 워드프레스 관리 → "블로그를 추가하세요"
→ 멀티서비스 결제(월 4,000원) → 블로그 이름·ID·PW → 루트 도메인에서 **추가한 서브도메인 선택** → 완료

### 3. 세팅 (2강 순서 반복 — 2번째부터 5분)
[`10-블로그-만들기-참고.md`](10-블로그-만들기-참고.md)의 Part B 그대로:
1. 브릿지 테마 어시스턴트 비활성화·삭제
2. **사이트 제목** — 제휴 주제에 맞게 (예: "여행·가전 할인쿠폰 모음")
3. 태그라인 · 파비콘 (ChatGPT)
4. Rank Math 시작 마법사 (유료 기능 체크 해제)
5. GeneratePress 설치·활성화
6. 알팩: Seen Analytics · 빠른 버튼 · Header & Footer · Adx 매니저(robots.txt)
7. **카테고리** — 제휴 주제별 (심사 중이 아니므로 여러 개 OK)
8. 메뉴: Header + Footer 2개 생성
9. **정책 페이지**: 개인정보처리방침 + DMCA (실제 정보로 수정) → Footer에 배치

### 4. 검색엔진 등록 4곳 (2강 반복)
- 네이버 서치어드바이저 / 구글 서치콘솔 / Bing / Daum
- ⚠️ 반드시 `https://`
- ⚠️ 소유권 확인 태그를 **다른 블로그와 혼동하지 말 것**. 사이트별로 기록
- 사이트맵(`/sitemap_index.xml`) + RSS(`/feed`) 제출

### 5. 북마크 정리
- `세컨 관리자` / `세컨 메인` 형태로 사이트별 북마크

→ 완료하면 `data/niche.yaml`의 `second_blog` 채우기

## 서드 블로그 (세컨이 궤도에 오른 뒤)

세컨과 **동일한 절차**를 다른 서브도메인·다른 니치로 반복합니다.
- 세컨: 여행 할인쿠폰 → 서드: 가전 모델 리뷰 처럼 주제를 분리
- 같은 글을 세컨/서드에 **복제하지 마세요** (중복 콘텐츠)
- 서드는 세컨의 성과 데이터(`data/metrics.csv`)를 보고, **수익이 확인된 방향**으로 확장

> 확장 판단 기준: 세컨 블로그에서 최소 몇 건이라도 **전환(수익)**이 나오는지 확인한 뒤 서드로.
> 근거 없이 사이트 수만 늘리면 관리·품질 부담만 커집니다.

## 캐시 문제 (자주 발생)

사이트맵/RSS 등록이 안 되거나 변경이 반영 안 되면:
> 호스팅 콘솔 → 워드프레스 관리 → **모든 CloudFront 캐시 삭제** → 재시도

강사가 4강에서 반복 강조: "**대부분의 워드프레스 오류는 캐시 문제**"

## 사이트가 늘수록 (경고)

각 사이트마다 업데이트·백업·정책 페이지·검색엔진·분석 비용이 **누적**됩니다.
사이트 수보다 각 사이트의 품질·수익성이 우선입니다.
